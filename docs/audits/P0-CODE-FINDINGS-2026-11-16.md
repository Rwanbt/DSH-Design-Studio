# P0 targeted source inspection — 2026-11-16

Scope: four inspected files from external repositories, plus OpenPencil manifest/README. **Partial, not an exhaustive audit.**

## Source-backed findings

1. `AndreTheAccelerator/dsh-design-canvas/host/model.js` (blob `dffd3151b93f2fa0f4bd4b8d603e6d99b86a49f0`): pure JS document model with operation/property validation, frame nesting and CSS-like layout. Its supported layer types are rect/ellipse/text/image/frame, **not SVG paths**. Therefore its model cannot serve unchanged as a native vector representation.
2. `AndreTheAccelerator/dsh-design-canvas/host/store.js` (blob `2d27aa6179ec05dc316401f092aea46d76e871dc`): read/write operations serialize with in-memory promise chains; it notices external disk edits using mtime/size, and writes a temporary file then renames. **mtime/size are not sufficient** as a sole conflict detector for native source files; compare content hashes before committing. Exact same-size edits within timestamp resolution can be missed.
3. `Sal7one/DSH-Design-Studio/lib/client/src/element-picker.js` (blob `6685209ffd1f26ff64a805ca02da8235a80285c3`): computes CSS selectors from id or tag + nth-of-type and style/rect descriptions from a same-origin iframe. These identifiers can change when DOM structure changes and do not supply source byte ranges. Integrating manual source editing requires a source mapper, not just this picker.
4. `zhang-guo-wen/dsh-web-design/README.en.md` (blob `4d2485864a89ebe1d9ba2c56858de67fa681f13c`): declares target-range source writeback and a companion `.design.json` draft. It explicitly skips edits not uniquely located in source or generated by scripts; source algorithm itself must still be inspected.
5. `ZSeven-W/dsh-openpencil/package.json` (blob `97ea7aa3a6c9da046509ac7ea8ec12a1c8f7f84c`): Node >=24.11, managed editor runtime staging and a browser client. Integration likely heavier than Design Canvas; inspect the actual native editor runtime and SVG round-trip before importing.
6. `ZSeven-W/openpencil/LICENSE` (blob `0dec8929ada31c1b4a60e64410e283a538ca9dfc`): MIT at root, not proof of license/round-trip compatibility for all packages and assets.

## First implementation experiment

`src/native-patch.mjs` is an original, dependency-free and pure prototype, not copied from upstream. It accepts source text, format (SVG/HTML/CSS), SHA-256 revision and exact source-span preconditions; it rejects stale/overlapping edits, leaves unrelated source untouched and returns inverse patches for undo. It has **no file writes, parser, element selection, sandbox, CSS model or UI**, so it is **not** a full editor.

### Local execution evidence

Command executed in isolated Node environment:

```sh
node --test /mnt/data/dsh-core/tests/native-patch.test.mjs
```

Result observed: **11 tests, 11 passed, 0 failed**, runtime 166.6 ms. This command was executed on locally staged equivalent source and test files **before** their GitHub upload. The exact remote commit must be re-verified via CI after the push; do not claim remote CI PASS from this result.

### Remaining limitations

- Does not parse or validate HTML/SVG/CSS syntax (patches are **text-level**, not semantic).
- UTF-16 text indices are not UTF-8 byte ranges; source adapter must handle encoding/BOM and stable mapping.
- Does not ensure source is trustworthy or sandbox untrusted scripts.
- No OS-level atomic disk write, symlink check, safe path API or optimistic recheck at commit point.
- Does not support overlapping patches by design; collaborative merge is not implemented.
- In-memory undo inverse only; persisted history will need dedicated storage.
- No DSH native runtime integration or GUI yet.
